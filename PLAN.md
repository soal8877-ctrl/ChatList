# План реализации ChatList

Поэтапный порядок работ по спецификации из `PROJECT.md`.

---

## Этап 0. Подготовка проекта

1. Проверить и обновить зависимости в `requirements.txt`:
   - PyQt6
   - httpx (или requests)
   - python-dotenv
   - pyinstaller (для сборки exe)
2. Создать структуру каталогов:
   - `db.py` — работа с SQLite
   - `models.py` — логика моделей и промтов
   - `network.py` — HTTP-запросы к API
   - `main.py` — GUI и связка модулей
3. Добавить `.env.example` с именами переменных для API-ключей (без самих ключей).
4. Описать схему БД в `DATABASE.md` и реализовать инициализацию БД при первом запуске.

**Результат:** каркас проекта, пустая БД создаётся автоматически.

---

## Этап 1. Модуль базы данных (`db.py`)

1. Реализовать подключение к SQLite (файл `chatlist.db` в каталоге приложения).
2. Создать функцию `init_db()` — создание таблиц `prompts`, `models`, `results`, `settings` (см. `DATABASE.md`).
3. Реализовать CRUD для каждой таблицы:
   - **prompts** — добавление, список, поиск, удаление
   - **models** — добавление, список активных, обновление `is_active`, редактирование
   - **results** — запись выбранных результатов, список, поиск
   - **settings** — чтение/запись пар «ключ — значение»
4. Добавить начальные данные (seed): 1–2 модели-заглушки и базовые настройки, если таблицы пусты.

**Результат:** все операции с постоянным хранилищем инкапсулированы в `db.py`.

---

## Этап 2. Модуль моделей (`models.py`)

1. Описать dataclass-структуры: `Prompt`, `Model`, `Result`, `TempResult` (временная строка в памяти).
2. Реализовать загрузку активных моделей: `get_active_models()` → обращение к `db.py`.
3. Реализовать работу с промтами:
   - сохранение нового промта в `prompts`
   - загрузка списка сохранённых промтов
4. Реализовать логику временной таблицы результатов (in-memory):
   - `clear_temp_results()`
   - `add_temp_result(model_name, response, selected=False)`
   - `get_temp_results()`
   - `get_selected_temp_results()`
5. Реализовать сохранение выбранных результатов в `results` через `db.py`.

**Результат:** бизнес-логика отделена от GUI и сети.

---

## Этап 3. Модуль сети (`network.py`)

1. Подключить `python-dotenv` — чтение API-ключей из `.env` по имени переменной из таблицы `models`.
2. Реализовать базовый клиент HTTP (httpx) с таймаутом и обработкой ошибок.
3. Реализовать адаптеры для типов API (минимально — один универсальный, затем расширение):
   - OpenAI-совместимый формат (`/v1/chat/completions`)
   - DeepSeek, Groq — через тот же или отдельные адаптеры
4. Функция `send_prompt(model: Model, prompt: str) -> str`:
   - берёт ключ из `.env` по `api_key_env`
   - отправляет запрос на `api_url` с `api_id`
   - возвращает текст ответа или сообщение об ошибке
5. Функция `send_prompt_to_all(models, prompt) -> list[TempResult]` — параллельная или последовательная отправка во все активные модели.

**Результат:** отправка промта в несколько нейросетей из одного места.

---

## Этап 4. Графический интерфейс — каркас (`main.py`)

1. Заменить минимальное окно на полноценный `MainWindow` с разделами:
   - **верх:** ввод промта + кнопка «Отправить»
   - **середина:** таблица временных результатов (модель | ответ | чекбокс)
   - **низ:** кнопки «Сохранить», «Новый запрос»
2. Добавить комбобокс или список сохранённых промтов — выбор из `prompts`.
3. Подключить `QTableWidget` или `QTableView` + модель для временных результатов.
4. Реализовать индикатор загрузки на время запросов (disabled-кнопки или progress bar).

**Результат:** визуальная структура приложения готова, без полной логики.

---

## Этап 5. Связка GUI и логики (основной сценарий)

1. **Ввод промта:**
   - пользователь вводит текст или выбирает сохранённый промт
   - при новом промте — опционально сохранить в `prompts`
2. **Отправка (кнопка «Отправить»):**
   - очистить временную таблицу
   - получить активные модели из `models.py`
   - вызвать `network.send_prompt_to_all()`
   - заполнить таблицу на экране
3. **Отображение результатов:**
   - каждая строка: название модели, текст ответа, чекбокс `selected`
4. **Сохранение (кнопка «Сохранить»):**
   - собрать строки с `selected = True`
   - записать в `results` через `models.py` → `db.py`
   - очистить временную таблицу
5. **Новый запрос:**
   - очистить поле ввода и временную таблицу
   - при следующей отправке — создать таблицу заново

**Результат:** рабочий цикл из спецификации (п. 4.1–4.5) реализован.

## Этап 9. AI-ассистент для улучшения промтов

Реализация п. 7 из `PROJECT.md`.

### Цель

Помочь пользователю улучшить промт перед отправкой в несколько моделей: одна модель OpenRouter анализирует текст и предлагает улучшенную версию, 2–3 альтернативы и (опционально) адаптации под разные задачи.

### Зависимости

- Этапы 0–6 (готовы): `network.py`, `models.py`, `main.py`, OpenRouter-клиент.
- Активная модель-ассистент в `models` или отдельная настройка в `settings`.

---

### Этап 9.1. Настройки и модель ассистента

1. Добавить ключи в таблицу `settings` (через seed/migration в `db.py`):
   - `assistant_model_id` — ID модели OpenRouter для улучшения (например `openrouter/free` или конкретная `:free`-модель).
   - `assistant_enabled` — `1` / `0`, включён ли ассистент.
2. Расширить диалог **«Настройки»** в `main.py`:
   - выпадающий список моделей из таблицы `models` (только активные или все);
   - подсказка: «Модель для улучшения промтов».
3. Реализовать в `models.py`:
   - `get_assistant_model() -> Model | None` — загрузка выбранной модели;
   - `get_assistant_settings() -> dict` — чтение настроек ассистента.

**Результат:** пользователь может указать, какая модель улучшает промты.

---

### Этап 9.2. Логика улучшения промта (`prompt_assistant.py`)

Создать отдельный модуль (не смешивать с CRUD-моделями в `models.py`).

1. Описать dataclass `PromptSuggestion`:
   - `label: str` — название варианта («Улучшенный», «Для кода», «Краткий»);
   - `text: str` — текст промта.
2. Описать dataclass `PromptImprovementResult`:
   - `original: str`;
   - `improved: str`;
   - `alternatives: list[PromptSuggestion]` (2–3 шт.);
   - `adaptations: list[PromptSuggestion]` — код / анализ / креатив (опционально).
3. Реализовать системный промт (константа `ASSISTANT_SYSTEM_PROMPT`):
   - попросить модель вернуть **строго JSON** с полями:
     ```json
     {
       "improved": "...",
       "alternatives": ["...", "...", "..."],
       "adaptations": {
         "code": "...",
         "analysis": "...",
         "creative": "..."
       }
     }
     ```
   - указать: сохранять смысл, улучшать ясность, не добавлять лишнего.
4. Функция `improve_prompt(text: str, model: Model) -> PromptImprovementResult | str`:
   - вызов `network.send_prompt(model, user_message)` с system + user сообщениями;
   - парсинг JSON из ответа (с fallback: если JSON битый — вернуть сырой текст как `improved`);
   - обработка ошибок сети/API — вернуть строку ошибки.
5. Добавить `build_assistant_messages(original: str) -> list[dict]` — формирование messages для OpenRouter.

**Результат:** улучшение промта инкапсулировано в одном модуле, GUI не знает деталей API.

---

### Этап 9.3. Расширение `network.py` (при необходимости)

1. Добавить функцию `send_chat(model, messages, timeout) -> str`:
   - общий метод для произвольного списка messages (system + user);
   - переиспользовать существующий OpenRouter-клиент, заголовки, retry, логирование.
2. Оставить `send_prompt()` для основного сценария без изменений.
3. Логировать запросы ассистента через `logger.py` (статус `assistant_ok` / `assistant_error`).

**Результат:** ассистент и основная отправка используют один HTTP-слой.

---

### Этап 9.4. GUI — кнопка и фоновый запрос

1. В блок **«Промт»** (`main.py`) добавить кнопку **«Улучшить промт»** рядом с «Отправить».
2. По нажатию:
   - проверить, что поле промта не пустое;
   - проверить, что выбрана модель-ассистент в настройках;
   - запустить `ImprovePromptWorker(QThread)` — аналог `SendWorker`;
   - на время запроса блокировать кнопки (как при «Отправить»).
3. При успехе — открыть диалог с результатами; при ошибке — `QMessageBox`.

**Результат:** улучшение не блокирует UI и не мешает основному сценарию.

---

### Этап 9.5. GUI — диалог результатов

Создать `PromptImprovementDialog(QDialog)`:

| Блок | Содержимое |
|------|------------|
| Исходный промт | `QPlainTextEdit`, только чтение |
| Улучшенный | текст + кнопка **«Подставить»** |
| Альтернативы | список или вкладки (2–3 варианта), у каждого кнопка **«Подставить»** |
| Адаптации | опционально: «Код», «Анализ», «Креатив» — каждая с кнопкой **«Подставить»** |

Поведение кнопки **«Подставить»**:
- скопировать выбранный текст в `prompt_edit` главного окна;
- закрыть диалог (или оставить открытым — по желанию, по умолчанию закрыть);
- не сохранять автоматически в БД (пользователь сам решает, нажать ли «Сохранить промт»).

**Результат:** пользователь видит все варианты и выбирает один кликом.

---

### Этап 9.6. Связка с основным сценарием

1. После подстановки текста в поле ввода — пользователь может сразу нажать **«Отправить»**.
2. Не очищать временную таблицу результатов при улучшении промта.
3. Не вызывать улучшение автоматически — только по кнопке.
4. Опционально: чекбокс в настройках «Спрашивать перед заменой промта» (можно отложить на v2).

**Результат:** ассистент — вспомогательный шаг перед отправкой, не ломает п. 4.1–4.5.
