# План реализации ChatList

Поэтапный порядок работ на основе `PROJECT.md`. Каждый этап завершается рабочей, проверяемой версией.

---

## Этап 0. Каркас проекта

1. Зафиксировать структуру каталогов и модулей из спецификации:
   - `main.py` — GUI
   - `db.py` — доступ к SQLite
   - `models.py` — работа с нейросетями (список, активность)
   - `network.py` — HTTP-запросы к API
2. Обновить `requirements.txt`: PyQt6, httpx (или requests), python-dotenv.
3. Добавить `.env.example` с именами переменных для API-ключей (без самих ключей).
4. Убедиться, что `.env` уже в `.gitignore`.

**Критерий готовности:** проект запускается, зависимости ставятся одной командой.

---

## Этап 1. База данных (`db.py`)

1. Описать и создать схему SQLite по `DATABASE.md`:
   - `prompts`, `models`, `results`, `settings`
2. Реализовать инициализацию БД при первом запуске (`CREATE TABLE IF NOT EXISTS`).
3. Добавить CRUD-операции:
   - промты: создать, список, поиск по тексту/тегам
   - модели: список, фильтр `is_active=1`, CRUD
   - результаты: сохранение выбранных строк, список, удаление
   - настройки: get/set по ключу
4. Инкапсулировать все SQL только внутри `db.py`.

**Критерий готовности:** БД создаётся, записи пишутся и читаются без GUI (простые вызовы/скрипт проверки).

---

## Этап 2. Модели и сеть (`models.py`, `network.py`)

1. В `models.py`:
   - получить активные модели из БД
   - сопоставить `api_id` с переменной окружения из `.env`
   - валидировать, что ключ задан для активной модели
2. В `network.py`:
   - единый интерфейс отправки промта (модель + текст → ответ)
   - обработка ошибок сети/API (таймаут, HTTP-ошибки)
   - на первом шаге — один провайдер (например OpenAI-совместимый API)
3. Подготовить сиды: 1–2 тестовые записи в `models` для проверки.

**Критерий готовности:** один промт уходит в активную модель и возвращается текст ответа.

---

## Этап 3. Временная таблица результатов (в памяти)

1. Ввести структуру строки результата в памяти:
   - название модели, текст ответа, `selected`, служебные id модели/промта
2. Реализовать жизненный цикл:
   - создать после ответов всех моделей
   - очистить при «Сохранить»
   - полностью сбросить при новом промте
3. Не писать временные строки в SQLite.

**Критерий готовности:** цикл «запрос → временный список → очистка» работает без UI.

---

## Этап 4. Основной интерфейс (`main.py`) — MVP

1. Экран ввода промта:
   - поле текста
   - выбор сохранённого промта из `prompts`
   - кнопка «Отправить»
2. Таблица результатов (временная):
   - модель, ответ, чекбокс `selected`
3. Кнопка «Сохранить»:
   - записи с `selected=True` → `results`
   - очистка временной таблицы
4. Связать UI с `db.py`, `models.py`, `network.py`.
5. Запросы к API выполнять так, чтобы GUI не зависал (фоновый поток / `QThread`).

**Критерий готовности:** полный сценарий из п. 4 `PROJECT.md` проходит вручную.

---

## Этап 5. Управление данными в GUI

1. Простой экран/диалог управления моделями (имя, url, `api_id`, активность).
2. Просмотр и повторное использование сохранённых промтов.
3. Просмотр сохранённых результатов из `results`.
4. Базовые настройки программы через таблицу `settings` (например путь к БД, таймаут).

**Критерий готовности:** пользователь может настроить модели и смотреть историю без правки кода/SQL.

---

## Этап 6. Дополнительно (по `PROJECT.md`, опционально)

1. Поиск и сортировка во всех таблицах UI.
2. Экспорт выбранных результатов в Markdown / JSON.
3. Адаптеры под разные типы API (OpenAI, DeepSeek, Groq и т.д.).
4. Логи запросов (файл или отдельная таблица).

**Критерий готовности:** выбранные опции реализованы и задокументированы в README.

---

## Этап 7. Сборка и документация

1. Обновить README: установка, `.env`, запуск, сборка exe.
2. Собрать исполняемый файл (PyInstaller), проверить запуск на чистой машине/без venv.
3. Сверить реализацию с `PROJECT.md` и `DATABASE.md`.

**Критерий готовности:** приложение устанавливается и используется по инструкции без доступа к исходникам разработки.

---

## Порядок зависимостей этапов

```
0 → 1 → 2 → 3 → 4 → 5 → 6 → 7
         ↑         │
         └─────────┘  (UI опирается на БД, сеть и временную таблицу)
```
