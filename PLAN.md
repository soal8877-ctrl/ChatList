# План реализации ChatList

Поэтапный порядок работ на основе `PROJECT.md`. Каждый этап завершается рабочей, проверяемой версией.

---

## Этап 0. Каркас проекта

1. Зафиксировать структуру каталогов и модулей из спецификации:
   - `main.py` — GUI
   - `db.py` — доступ к SQLite
   - `models.py` — работа с нейросетями (список, активность)
   - `network.py` — HTTP-запросы к API
2. Обновить `requirements.txt`: PyQt6, httpx (или requests), python-dotenv.
3. Добавить `.env.example` с именами переменных для API-ключей (без самих ключей).
4. Убедиться, что `.env` уже в `.gitignore`.

**Критерий готовности:** проект запускается, зависимости ставятся одной командой.

---

## Этап 1. База данных (`db.py`)

1. Описать и создать схему SQLite по `DATABASE.md`:
   - `prompts`, `models`, `results`, `settings`
2. Реализовать инициализацию БД при первом запуске (`CREATE TABLE IF NOT EXISTS`).
3. Добавить CRUD-операции:
   - промты: создать, список, поиск по тексту/тегам
   - модели: список, фильтр `is_active=1`, CRUD
   - результаты: сохранение выбранных строк, список, удаление
   - настройки: get/set по ключу
4. Инкапсулировать все SQL только внутри `db.py`.

**Критерий готовности:** БД создаётся, записи пишутся и читаются без GUI (простые вызовы/скрипт проверки).

---

## Этап 2. Модели и сеть (`models.py`, `network.py`)

1. В `models.py`:
   - получить активные модели из БД
   - сопоставить `api_id` с переменной окружения из `.env`
   - валидировать, что ключ задан для активной модели
2. В `network.py`:
   - единый интерфейс отправки промта (модель + текст → ответ)
   - обработка ошибок сети/API (таймаут, HTTP-ошибки)
   - на первом шаге — один провайдер (например OpenAI-совместимый API)
3. Подготовить сиды: 1–2 тестовые записи в `models` для проверки.

**Критерий готовности:** один промт уходит в активную модель и возвращается текст ответа.

---

## Этап 3. Временная таблица результатов (в памяти)

1. Ввести структуру строки результата в памяти:
   - название модели, текст ответа, `selected`, служебные id модели/промта
2. Реализовать жизненный цикл:
   - создать после ответов всех моделей
   - очистить при «Сохранить»
   - полностью сбросить при новом промте
3. Не писать временные строки в SQLite.

**Критерий готовности:** цикл «запрос → временный список → очистка» работает без UI.

---

## Этап 4. Основной интерфейс (`main.py`) — MVP

1. Экран ввода промта:
   - поле текста
   - выбор сохранённого промта из `prompts`
   - кнопка «Отправить»
2. Таблица результатов (временная):
   - модель, ответ, чекбокс `selected`
3. Кнопка «Сохранить»:
   - записи с `selected=True` → `results`
   - очистка временной таблицы
4. Связать UI с `db.py`, `models.py`, `network.py`.
5. Запросы к API выполнять так, чтобы GUI не зависал (фоновый поток / `QThread`).

**Критерий готовности:** полный сценарий из п. 4 `PROJECT.md` проходит вручную.

## Этап 8. AI-ассистент для улучшения промтов (`PROJECT.md` § 7)

Функция принимает исходный промт, отправляет его в одну модель и возвращает улучшенную версию, 2–3 альтернативные переформулировки и (опционально) адаптации под разные типы задач. Результат встраивается в UI; любой вариант можно подставить в поле ввода одним кликом.

### 8.1. Настройка «модель-улучшатель»

1. Добавить ключ `improve_model_id` в таблицу `settings` (id модели из `models`).
2. В диалоге **Настройки** (`SettingsDialog`) добавить выпадающий список **«Модель для улучшения промтов»**, заполняемый из `db.list_models()`.
3. Если ключ не задан — использовать первую активную модель.

**Файлы:** `db.py` (get/set setting), `dialogs.py` (SettingsDialog).

### 8.2. Системный промт для улучшения

1. Создать модуль `prompt_improver.py`.
2. Сформировать системный промт с инструкциями для модели:
   - Принять исходный текст пользователя.
   - Вернуть JSON-объект с полями:
     - `improved` — одна улучшенная версия;
     - `alternatives` — массив из 2–3 переформулировок;
     - `adaptations` — объект `{ "code": "...", "analysis": "...", "creative": "..." }` (адаптации промта под тип задачи).
   - Промт должен быть на том же языке, что и исходный текст.
3. Составить `messages` для chat/completions:
   ```json
   [
     {"role": "system", "content": "<системный промт>"},
     {"role": "user",   "content": "<исходный промт пользователя>"}
   ]
   ```
4. Функция `improve_prompt(model: ActiveModel, prompt: str) -> ImproveResult`:
   - Отправляет запрос через существующий `network.py` / `httpx`.
   - Парсит JSON из ответа (с fallback: если модель вернула не JSON — показать сырой текст как `improved`, остальное пустое).
   - Возвращает `ImproveResult` (dataclass):
     - `improved: str`
     - `alternatives: list[str]`
     - `adaptations: dict[str, str]`

**Файлы:** новый `prompt_improver.py`; переиспользует `network.py` для отправки.

### 8.3. Фоновый поток

1. Создать `ImproveWorker(QThread)` в `main.py` (аналог `SendWorker`):
   - Сигналы: `finished_ok(ImproveResult)`, `finished_err(str)`.
   - Получает модель из `settings` → `improve_model_id` → `get_active_models`.
   - Вызывает `improve_prompt()`.
2. Во время работы блокировать кнопку «Улучшить», показывать статус «Улучшение…».

**Файлы:** `main.py`.

### 8.4. Диалог результата «Улучшение промта»

1. Новый `ImproveDialog(QDialog)` в `dialogs.py`:
   - **Исходный промт** — `QTextBrowser`, read-only.
   - **Улучшенный промт** — `QTextBrowser`, кнопка **«Подставить»**.
   - **Альтернативы** (2–3 штуки) — `QListWidget` / вертикальный список из `QTextBrowser`, у каждого кнопка **«Подставить»**.
   - **Адаптации** (код / анализ / креатив) — `QTabWidget` или 3 вкладки, у каждого кнопка **«Подставить»**.
   - Кнопка **«Закрыть»**.
2. Все кнопки «Подставить» эмитят сигнал `apply(str)` → главное окно записывает текст в `prompt_edit`.

**Файлы:** `dialogs.py`.

### 8.5. Кнопка «Улучшить промт» в главном окне

1. Добавить `QPushButton("Улучшить промт")` рядом с полем ввода (`prompt_edit`), между строкой промта и строкой кнопок «Отправить / Сохранить».
2. При клике:
   - Прочитать текст из `prompt_edit`; если пусто — предупреждение.
   - Запустить `ImproveWorker`.
   - По `finished_ok` — открыть `ImproveDialog`.
   - По `finished_err` — показать ошибку.
3. После «Подставить» в диалоге:
   - Записать выбранный текст в `prompt_edit`.
   - `current_prompt_id = None` (новый промт).
   - Закрыть диалог.

**Файлы:** `main.py`.

### 8.6. Порядок реализации (подэтапы)

```
8.1 (settings) → 8.2 (prompt_improver.py) → 8.3 (worker) → 8.4 (dialog) → 8.5 (кнопка)
```

Каждый подэтап тестируется отдельно:
- 8.1 — настройка сохраняется/читается.
- 8.2 — `improve_prompt()` возвращает `ImproveResult` в CLI.
- 8.3 — worker эмитит сигнал в тестовом окне.
- 8.4 — диалог открывается с мок-данными.
- 8.5 — полный цикл: ввёл промт → «Улучшить» → выбрал вариант → подставил → «Отправить».

### Критерий готовности

Пользователь вводит промт, нажимает «Улучшить промт», видит улучшенную версию, альтернативы и адаптации, подставляет любой вариант в поле ввода одним кликом и отправляет его в модели.
